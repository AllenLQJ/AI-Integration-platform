# 本机只读看板

看板采用任务列表、协作记录、任务详情三栏布局。前端是独立静态模块，使用版本化 HTTP 展示 API，不直接访问数据库或执行器。安装包包含静态资源，运行时无需 Node.js。

## 打开

```sh
agent-hub dashboard
```

可通过已有 `--data-dir` 参数或 `AGENT_HUB_DATA_DIR` 环境变量选择数据目录。命令连接该目录的后台服务并打开默认浏览器。代码升级后，旧后台进程仍运行旧代码；请在已有任务结束后按正常维护流程重启 Hub，再打开看板。

命令为本机浏览器签发一次性、60 秒有效的票据，交换为最长 8 小时的只读会话。票据使用 URL fragment 传递，页面立即清除它；浏览器不会接收 Hub 的管理令牌。链接过期后重新运行打开命令。不要分享登录链接或将真实数据放入源码。

可以用不同 `--data-dir` 分别打开多个本机 Hub 看板；只读会话按服务端口区分。后台服务重启后需要重新运行打开命令。

## 数据含义

- 左侧按任务执行器、执行状态、关键词筛选，并分页加载。
- 中间分别展示任务输入、已记录的过程消息和最终结果，以及按游标读取的事件。
- 任务执行结束并不表示独立验收通过，详情区分别显示这两个状态。
- 续接、切换执行器和独立审核是不同关系。没有明确记录的 Agent 派发关系不做推测。
- 过程消息可能被执行器截断；自定义插件或命令执行器可能只返回结果。页面不会补造工具调用、调用者或完整聊天历史。
- 看板不提供派发、取消、总控接管或任意文件下载，也不改变任务租约。

## 接口与边界

展示接口位于 `/dashboard/api/v1/`，包括 `tasks`、`agents`、`tasks/{id}`、`tasks/{id}/events`。接口使用独立只读会话，不接受该会话调用管理 RPC。服务仅监听回环地址；跨设备安装指各设备独立运行，不表示公开远程管理接口。

前端 `api.mjs` 处理传输和会话，`state.mjs` 处理请求序列与事件游标，页面与样式分别放在 `app.mjs`、`style.css`。更换前端框架不需要修改执行器协议。

服务端展示投影显式选择字段；账号、设备配置、任务数据库和日志仍在各设备自己的数据目录。任务文本和原始事件属于用户数据，即使经过脱敏，也应只给有权查看本机任务的人访问。

## 开发检查

```sh
python -m unittest discover -s tests
node --test tests/frontend/*.mjs
python -m pip wheel . --no-deps
```

前端不依赖第三方 CDN、字体、构建工具或品牌固定名单。修改展示契约时同步检查 API 与页面测试；打包时确认静态文件包含在 wheel 内。
