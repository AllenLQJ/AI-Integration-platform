# 第二轮可靠性与性能优化验证

日期：2026-10-25。工作分支：`codex/reliability-dashboard-performance`。

## 修改内容

1. 对远端停止未确认的任务，在终态发布及释放槽位之前持久化工作区隔离；同目录已排队任务和新任务均受保护。已确认停止，以及执行器尚未启动就取消的任务，不会误隔离。保留续接接口原有的 `REMOTE_STATE_UNKNOWN` 错误码。
2. 详情刷新包含验收检查证据与验收策略，支持总体状态不变时更新证据。
3. 单个结果文件缺失、损坏或不是 JSON 对象时，保留执行和验收真值并显示结果不可用；不影响任务链其他节点。结果引用保留小型取消/不确定状态证据。相关 ETag 同时检查数据库及结果文件状态，覆盖删除和恢复。
4. 事件首次读取最近 200 条；浏览器窗口最多保留 1,000 条及约 2 MiB 序列化数据，旧 DOM 同步移除。支持 `before_seq` 历史分页，历史页不会被轮询覆盖；返回最新后恢复实时事件。超大单条事件显示摘要。
5. 验收工作项以递归 SQL 查询当前任务家庭，批量读取验收概要、检查、产物和每任务最近 20 条事件，在内存中计算层级；保留原有顺序、叶节点选择和 controller 语义。

## 证据与边界

- 本地合成的 50 次连续尝试：读取查询从 1,477 次降为 7 次（包含递归 CTE）；深度仍为 50。独立复核通过 `EXPLAIN QUERY PLAN` 确认递归查询使用 `tasks_parent` 索引。
- 缺失/损坏/数组 JSON 三种结果异常均覆盖单任务和整链读取，并验证其他节点答案保留。
- 使用真实前端模块的模拟 DOM，覆盖证据单独更新、事件窗口与 DOM 淘汰、历史翻页、轮询保持以及返回最新。
- 新历史 HTTP 路由保留认证，拒绝混合方向、重复游标和越界游标。
- 一次独立代码复核发现启动前取消误隔离，已先添加失败回归，再修复；相关 14 项专项回归通过。没有进行第二轮重复复核。
- 完整回归暴露 `test_crash_window_with_interrupted_review_fails_closed_with_real_reason` 和 `test_restart_while_review_running_does_not_resubmit_model` 的同类测试时序问题：它们在记录为 running、执行器尚未启动时就关停，却要求执行器已经调用一次。后者独立重复 5 次有 2 次失败。统一修正测试助手 `reviewing()`，等待对应审核任务实际派发后再模拟中断，保留原有恢复状态、原因、证据和调用次数断言；修正后重复 5 次均通过，完整审核模块 30 项通过。
- 暂停后恢复时定向复现了 HTTP 会话拒绝用例的 Windows `10053` 连接中止：30 次运行中 6 次出错，发生于小体积 POST 正文尚未消费时关闭拒绝连接。修正为先发出原有 401/403，再在单一 200 毫秒期限内丢弃最多 4,096 字节的已声明正文，不解析票据、不授权操作；大正文、重复长度或传输编码直接跳过。相同 30 次运行修正后全部通过，新增分离请求头/正文及未完成正文的真实回环测试均通过。
- 测试使用本地假执行器与隔离临时数据，没有真实供应商端到端验收，也没有重启日常 Hub。远程跨平台 CI 需要后续推送才能执行。
