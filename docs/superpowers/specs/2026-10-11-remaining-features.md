## Muse 原会话取消

- 按当前官方网页实际使用的 `chat.cancel {session_id}` 契约取消原任务会话，不发送“请停止”作为新任务。
- 原本地等待进程树停止后用独立 MCP 连接清理，避免同一 Noise 连接有两个消费者。
- 取消、任务期限、正常后台退出共用清理路径；清理期限独立于任务已过期的期限。
- 核对本任务会话锁、发送基线、提交原文及后续用户消息；发现另一消息则不取消整个会话。
- 区分请求返回 cancelled 与已独立确认会话状态；稳定 history 与 completed/interrupted 状态才确认停止。失败保留锁，不自动重试取消。
- 允许配置固定既有 Muse session_id，验收只复用同一专用会话；不影响用户原有主会话。

## 跨机器 Hub 调度

- 使用已有 SSH 主机配置、BatchMode 与严格主机密钥检查，不开放 Hub HTTP 端口；目标机 Hub 仍仅监听回环地址。
- 控制器可将原有八个 MCP 工具转发到目标机；本地队列也可配置命名远端执行器。
- 目标机 Python、Hub 数据目录、执行器及工作区为显式配置，文件和凭据不自动同步。
- 提交后持久化目标任务 ID；结果附目标原生会话与工作区差异。续接和取消按原目标任务 ID 执行。
- 模型提交/续接不因网络错误自动重发；读断线或取消未确认须保留绑定，禁止不确定任务直接续发。
- 同一 Mac 的隔离 Hub 验证可证明转发与工作区管理，不能代替真实两机 SSH、目标机权限及平台验收。
