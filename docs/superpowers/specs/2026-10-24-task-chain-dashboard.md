# Task Chain Dashboard Design

Approved by the user on 2026-10-24: a chain list, left-to-right execution graph, chronological collaboration conversation, and selected execution details. Preserve the A-style quiet three-column layout and portable, read-only API boundary.

A graph node is one execution. Explicit parent_id gives continuation (resume_session present) or switch_executor; review_of.task_id gives review. Connected components of these explicit links form chains. No inference from prompt similarity, task sequence, executor identity or native session. Canonical chain id is the earliest root without an incoming valid edge (created,id order); cycles use earliest member. Dangling links and cycles must not hang or fabricate nodes. Review nodes do not override latest implementation status; active members are disclosed separately.

New GET /dashboard/api/v1/chains accepts the task-list filters and paging. Return {items,next_offset}; each item includes the existing summary fields plus root_task_id, latest_task_id, task_count, agents, active_count. id is the canonical chain id; title is root prompt; execution/verification/work status comes from latest non-review execution; updated is maximum member update. Sort chains by latest member update descending then id. Filters match a single member (q, state, agent together) but return the entire matching chain. Pagination is over chains.

GET /dashboard/api/v1/chains/{member_id} accepts any member and returns {chain,nodes,edges,messages,truncated,warnings}. nodes use the existing task summary. edges are {source,target,kind}, kind continuation/switch_executor/review. messages retain existing message fields with task_id and agent and are sorted by timestamp,task_id,id, null timestamp after dated records. Reuse existing detail redaction and role-aware dedup, never dedup across executions. Bound graph to 200 nodes and conversation to 500 messages and 1000000 text characters, disclose truncation. Do not silently mislabel graph subsets as complete. Prefer recent messages while retaining source labels. Existing task detail/events endpoints unchanged for selected-node inspection.

UI uses chain endpoints for list/conversation, original task detail/events for selected node. Show graph above conversation, with labeled edges, horizontal pan/scroll, zoom controls and reset, keyboard-focusable nodes and reduced-motion support. Node click scrolls to matching conversation message and changes right detail/events without leaving the chain. Poll chain to discover new nodes even without events; guard stale responses after rapid selections. Preserve graph viewport and existing conversation DOM where possible. Event tab explicitly refers to selected execution. Show cap/dangling/cycle notices. No manual merge or executor protocol changes in this release.
