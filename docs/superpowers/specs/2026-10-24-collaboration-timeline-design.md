# 协作与操作统一时间线设计

日期：2026-10-24
基线：f752bd8cc64a33c5e602f2289b4d083830f82d68
状态：用户于 2026-10-24 指定交给 Cursor 开发、Grok Bot 审核，按此设计进入实施。
工作目录：由当前聊天附加的 collaboration-timeline 隔离 worktree；D 盘主项目保持原状。

## 1. 用户明确提出的要求

- 展示两个模型之间的协作沟通过程，包含派发、过程回复、审查意见、返修、交付。
- 同时展示读文件、执行命令、跑测试等实际操作记录。
- 截图中每条任务输入、模型回复都可以独立展开和折叠。
- 提供全部展开、全部折叠。
- 用户选择 A：模型消息和操作记录按时间逐条混排。B（按执行分组再嵌套操作）没有被选择。

以下技术接口与默认交互作为实施方案；内部细节可在不改变用户需求和安全边界的前提下调整。

## 2. 目标与范围

沿用现有任务链、关系图、三栏看板和只读浏览器会话。中栏增加统一时间线，不另建前端、不增加前端框架或 CDN。用户能看清谁说了什么、哪次执行进行了何种操作，以及记录的来源与完整性。

实现包含三部分：已有执行器消息/操作事件的可靠采集；供外部总控或执行桥上报的明确入口；统一投影和折叠交互。

完成标准不包含宣称所有客户端的全部内部工具调用都可自动抓取。每个来源必须显示其实际采集覆盖范围；无法采集不等于没有操作。不能用模型描述“我读了文件”伪装成工具系统观测到的文件读取。

本功能只记录和展示。不会让模型自主互发新任务，也不会借此增加任务执行、取消、控制器接管或前端管理权限。

## 3. 已核对的当前实现

- dashboard.py 只从 task.prompt、kind=message 事件和最终 answer 生成对话；其他事件在选中执行的事件标签下展示。
- dashboard_chains.py 只合并明确的 parent_id 与 review_of.task_id，不推断相似任务；统一对话有节点、条数、字符数上限。
- app.mjs 当前将每条消息渲染为 article。原始事件已用 details，按稳定 ID 复用 DOM；消息正文变化时会重建，需单独保留折叠状态。
- processes.stream_events 能识别 Codex/Claude/Cursor 部分结构化工具记录，但只留下名称、状态和部分调用 ID。log_record 明确删除工具输入输出，不能依赖旧日志补出已丢弃信息。
- Grok 适配器轮询消息，但仅保留与本任务结束标记匹配的最终 send-message。可见过程回复尚未写 message 事件。其工具详情是否由上游公开，尚无完整验证证据。
- Muse 的回复匹配、会话归属和等待人工处理有现有约束，不能因展示进度而放宽。
- command v1 的 stdout 是结果协议，parse_cli_events=False；本功能不把任意 stdout 当事件解析。
- Store.event 可以追加事件，但没有面向外部总控的、受验证的活动写入工具。请求幂等键和控制器租约不能被当作已验证的聊天身份。

## 4. 方案比较与选择

A：统一时间线（用户已选）。按真实时间排列消息、读取、命令、测试、文件变更及必要系统提示；每条记录可独立折叠。便于回放交互顺序，操作多时通过默认折叠保持阅读密度。

B：按模型执行分组。每次执行下再展开消息和工具，层级清楚但跨模型交互顺序不直观，未选用。

数据侧建议沿用 Hub 已有事件通道，增加明确上报入口。扫描各客户端私人聊天库或猜测自由文本与工具调用的关系不作为采集依据，避免错误归属与不可移植的依赖。

## 5. 时间线记录与真实性

投影提供统一 TimelineEntry，保持现有 messages 与 events 接口兼容。建议字段：

- id、task_id、kind、timestamp、source、completeness。
- actor、recipient：可选的显示身份；未明确记录时显示未知，不从提示词猜测。
- provenance：executor_observed、controller_reported 或 legacy_summary。显示名称不是认证凭据。
- title、preview、text：折叠摘要与展开内容。
- operation_id、phase、status：操作记录的关联与状态；支持 started/completed/failed/unknown。
- operation：白名单字段，如 tool_name、相对文件路径、读取范围、command_display、工作目录显示名、exit_code、耗时、stdout/stderr 有界摘录、测试汇总。
- source_event_ids、truncated_fields：原事件定位和被截断部分。

开始/结束事件仍不可变地保存在事件表，同一次操作投影成一张状态更新的卡片。能关联时使用上游真实调用 ID；无法关联时保持独立记录，不按名称合并。不跨任务去重。模型消息的流更新使用上游消息 ID 与修订号或明确片段标识去重，避免重复追加整个累计文本。

排序使用 Hub 接收时间和事件 seq 作为稳定依据；任务输入和结果保留既有时间与稳定 ID。上游时间作为可选说明，不能让错误设备时钟扰乱默认顺序。

测试命令即使 exit_code=0，也仅代表该操作退出成功；测试数量只展示实际解析到的汇总。解析不出的数量显示未提供。任何活动记录均不得改写独立验收结果。

## 6. 采集与外部总控入口

### 6.1 执行器内自动采集

在真实结构化数据进入现有脱敏/裁剪逻辑时，先提取允许公开的最小操作字段，再做脱敏与预算处理。保留标准工具名称、调用 ID、状态、命令/相对路径、退出码与摘要；不保存完整读取文件内容、环境变量字典或原始凭据。

Codex/Claude/Cursor 按实际已有结构化记录建立映射和回归样本，无法识别的事件保留为明确的通用事件摘要。不要把命令字符串中的任意 test 字样当作已运行测试的证明。

Grok 仅从本任务 baseline 之后、已公开的 assistant send-message 采集过程回复，按 seq/updatedSeq 去重。忽略 thought 等非公开回复类型；过程消息不会改变最终结束标记、稳定 idle、取消所有权或不确定派发恢复规则。

Muse 只采集已归属本任务的可见回复；不跨会话抓历史，不破坏原有完成匹配、人工介入和取消规则。

插件可通过原有 event 回调提供规范活动；未提供时显示覆盖不足。command v1 保持结果协议，不能偷偷启用 stdout 事件解析。

### 6.2 外部总控 / 执行桥上报

建议增加一个本机管理 RPC/MCP record_activity，以及使用现有 Client 的 CLI 上报入口，用于 Codex 桌面总控或其他执行桥提供本来不经过 Hub 适配器的操作记录。

该入口只追加活动，不执行命令、不读取目标文件、不调用模型、不修改任务结果/验收/状态。浏览器只读 cookie 不能调用。需要当前本机管理认证；已有 controller 租约存在时，沿用 controller_id/epoch 校验。上报方自己填写的模型名称属于显示标签，前端标明“总控上报”，不冒充系统观测身份。

建议参数：request_id、task_id、event_id、activity，另含适用的 controller 字段。活动限定为 message/file_read/command/test/file_change/system；严格字段与尺寸验证。用独立收据表原子完成幂等校验及事件插入，相同请求和内容重试返回同一事件；相同键不同内容报冲突。可以在执行结束后补记本次任务，但不能因此复活执行或改变 updated 的执行语义。

外部总控可以将派发说明、复核反馈和自己的工具记录追加到其实际关联的任务，和执行器回复共同组成时间线。继续沿用明确的 parent/review 任务链关联；独立提交且无明确关联的任务仍不强行合并。跨 data-dir 聚合不在本轮范围。

新增工具意味着 MCP 工具数量及契约、能力说明、相关测试需要同步；旧工具兼容。已打开客户端通常需要刷新 MCP 配置或新聊天后才能使用新增工具。

### 6.3 必须明确的接入边界

上报入口本身不会自动截获 Codex 桌面的每次本机工具调用，也不会凭空获得 Grok/Muse 平台未公开的工具参数。要获得这些来源的操作详情，需要其总控/hook/执行桥实际调用上报入口，或上游已提供对应事件。

本轮提供入口、接入说明和可运行的合成演示；不安装全局桌面 hooks、不改账号设置、不抓私人聊天库。真实任务验收时，只有实际接入并取得证据的来源才标记有操作明细。其余明确显示“仅有消息/操作摘要/未接入操作记录”，不能声称全量自动采集已经完成。用户若要求现有桌面与 Grok 内部所有工具都零配置自动接入，需要另行核实它们实际可用的出口并扩大接入范围。

## 7. 前端折叠交互

保持用户截图中的布局。消息、操作均为可键盘访问的可展开卡片；折叠标题显示来源、记录类型、时间、状态、简短摘要，展开查看正文或参数/输出摘录。消息自身整块折叠，不只折叠其中一段日志。

顶部提供全部展开、全部折叠，作用范围明确为当前任务链“已载入的全部记录”；记录上限与缺失提示不隐藏。对消息与操作一并生效，不影响左侧任务、关系图或右侧详情。

建议默认：短消息展开；长消息与操作详情折叠。具体摘要阈值、视觉间距由实现者确定，并在交付时列明，不能改变完整性标记。

状态按任务链 ID + 稳定记录 ID 保存：
- 自动刷新、内容更新、开始变结束不得重置用户选择。
- 全部折叠后新到记录沿用折叠；全部展开后新记录沿用展开。
- 个别手动调整保留，切到其他任务链不污染；本页返回同一链应恢复。暂不承诺跨浏览器重启持久化。
- 点击图节点定位时允许临时展开定位的目标记录，不能展开整条链。展开按钮与右侧执行详情按钮彼此独立。
- 窄屏不横向溢出；长命令/输出可换行和限定高度滚动；支持 Enter/Space、清晰焦点、aria-expanded 与减少动画偏好。
- 保持现有安全文本渲染，不引入不安全 Markdown/HTML。

## 8. 展示 API、预算与安全

建议链详情新增 timeline 与可选 capture_coverage 字段，保留 messages、nodes、edges、warnings 的兼容含义。前端优先使用 timeline，旧服务缺少时回退现有 messages。原始事件标签保留，用于检查原 seq 与脱敏数据。

沿用 200 节点、500 条显示记录和 100 万文本字符总上限；消息与操作共同计入，截断明确提示。总预算必须包括操作参数/输出而不仅是 text；查询和归一化应有界，不读取无限原始日志或为每个节点无限扫描所有事件。分页与更早记录的产品扩展不在本轮强制范围，“全部”不得暗示未载入历史也已展开。

建议输入活动每条 JSON 不超过 64 KiB，命令/路径等标量字段各有上限，输出摘录默认合计不超过 16 KiB；实现者可下调，需文档化。先脱敏再裁剪。当前全路径遮盖逻辑不能直接放开：文件操作显示安全的工作区相对路径，区外只给受限显示名；命令摘录需保留有用参数同时屏蔽凭据。读取内容默认不全文留存。

记录是用户数据，不进入分发包、Git、文档或静态资源。单测/预览仅用合成数据。command v1 继续禁止把任意 stdout 或伪造 hub_event 变成管理事件。维护原有访问控制和只读展示边界。

## 9. 测试与验收

- 后端：结构化 CLI 消息、读取/命令/测试映射，原始调用 ID 关联与更新、未知类型、缺失字段、Unicode、超长内容、脱敏与预算。
- Grok/Muse：只记录本任务公开消息；重复轮询/消息修订不重复，thought/其他会话不泄露，最终标记/取消/等待人工语义保持。
- 上报：认证、只读 cookie 拒绝写入、未知任务、控制器过期、键冲突、并发幂等、终态补记、不改状态或验收。
- 展示：新旧服务/数据兼容，混排稳定，来源与完整性、事件界限和总预算一致。
- 前端：逐条/全部折叠、更新后保持、全折叠后新消息、跨链隔离、定位后展开、键盘、自动轮询/晚到响应、原图和详情交互不回归。
- 浏览器：隔离合成任务链演示两模型往返 + 读取 + 命令 + 测试 + 返修；桌面和窄屏检查。明确这是合成验收，不冒充真实模型自动工具抓取。
- 运行完整离线 Python、前端测试、wheel 静态资源校验。按需使用短 TEMP/TMP；区分通过、跳过、未验证范围。
- 实现后独立复核实际 diff 和测试结果，保留隔离分支/worktree。未获后续授权不合并、推送或重启日常 Hub。

模块拆分、内部类名、索引细节、摘要阈值、轻量样式与测试夹具由实施者确定；保持现有原生 ES 模块和 Python 标准库优先。不得通过这些选择扩大上游接入声明、放宽权限，或改动任务执行协议。
